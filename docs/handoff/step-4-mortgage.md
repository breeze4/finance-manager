`model_config = {"from_attributes": True}`. `MortgageScenarioCreate` excludes `is_active`. `MortgageScenarioUpdate` is all-optional `T | None = None`. Service's `update_scenario` filters out `is_active` even if a client sends it (proven by `test_update_does_not_change_is_active`).

## Service-vs-inline decision

Service extracted to `backend/app/services/mortgage_scenario_service.py`, matching coast fire's pattern. Router stays thin (HTTP concerns only). Activate-uniqueness invariant lives in `mortgage_scenario_service.activate_scenario`: a single `UPDATE ... WHERE id != :id AND is_active = TRUE` followed by setting the target row, all inside one `db.commit()`.

First-create auto-activation mirrors coast fire: `has_any = db.query(MortgageScenario.id).first() is not None` then `is_active=not has_any`. Verified by `test_create_returns_201_with_full_response` (first → active) and `test_create_second_does_not_auto_activate` (second → inactive).

## Edge cases

- **No crossover**: `investmentComparisonToRecharts` returns `crossoverMonth: undefined` when investment never overtakes mortgage equity. The chart simply renders without the `ReferenceDot` — no crash. The strategy tile still computes a recommendation either way (`payoff` if `interestSaved > investmentNetBenefit`, else `invest`).
- **Unpayable scenario** (monthly payment ≤ interest): `calculatePayoff` throws. `MortgageResults` catches and substitutes `{ months: 9999, totalInterest: principal * 10 }` to mirror the Pinia store's "essentially infinite" sentinel, and the chart adapters return empty rows rather than crashing — chart blocks render a "Chart unavailable" message.
- **Zero `additional_monthly_payment` and `lump_sum_payment`** (the default): `acceleratedPayoffMonths === basePayoffMonths`, `interestSaved = 0`, `totalAllContributions = 0`, `investmentGrossReturn = 0`. All tooltips still render valid values; recommendation defaults to `payoff` (`determineBetterStrategy(0, 0)` → `'payoff'` per its `>` comparison).

## Recharts row interface workaround

`MortgageBalanceRow`, `InterestComparisonRow`, `InvestmentComparisonRow` lack index signatures, so `ComparisonLineChart`'s `TRow extends Record<string, unknown>` constraint rejects them directly. Workaround at the chart call sites: `data={rows as unknown as Record<string, unknown>[]}`. Same trick coast fire uses.

## Tax-rate handling

`investment_tax_rate` is stored and surfaced as a percent (e.g. `20` for 20%). The math library expects a decimal — conversion happens at the `MortgageResults` boundary (`s.investment_tax_rate / 100` when feeding `calculateAfterTaxReturn`, `generateInvestmentComparisonChart`). Form↔state is whole-percent.

## Validation key boundary

`validateMortgageInputs` from `@/lib/math` uses **camelCase** keys (`principal`, `yearsLeft`, `interestRate`, `monthlyPayment`, `additionalMonthlyPayment`, `lumpSumPayment`, `investmentReturnRate`, `investmentTaxRate`). State is **snake_case** (matches API). The page maps state → camelCase at the validation boundary. The form references `errors?.camelCaseKey` so labels show errors correctly.
