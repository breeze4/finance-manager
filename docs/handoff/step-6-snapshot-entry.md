## `BalanceSnapshot` model

`backend/app/models/balance_snapshot.py`:

```py
SNAPSHOT_SOURCES = ("manual",)

class BalanceSnapshot(Base):
    __tablename__ = "balance_snapshots"
    id: Mapped[int]
    account_id: Mapped[int]                 # FK -> accounts.id, NOT NULL
    as_of_date: Mapped[date]
    balance: Mapped[float]                  # always positive; sign at display
    source: Mapped[str]                     # Enum("manual", name="snapshotsource")
    notes: Mapped[str | None]
    created_at, updated_at                  # server_default=func.now()
    account: Mapped["Account"] = relationship()  # no back_populates — Account
                                                  # owns no `snapshots` collection
    __table_args__ = (
        UniqueConstraint("account_id", "as_of_date",
                         name="uq_balance_snapshots_account_date"),
        Index("ix_balance_snapshots_account_id", "account_id"),
    )
```

- The `source` column is a SQLAlchemy `Enum(*SNAPSHOT_SOURCES, name="snapshotsource")`,
  matching the `accounttype` enum pattern from step 5. To add new source values
  in the future, write a fresh enum-alter migration (or convert to plain
  TEXT-with-CHECK) — the plan calls this out as forward-compatible.
- `Account` was intentionally **not modified** to add a `snapshots`
  back-populates collection — that file is owned by step 5 and step 6 must
  not touch it. The relationship is one-way; queries go through `db.query(BalanceSnapshot)`.

## API contract

### `POST /api/snapshots/batch`

Request body: `SnapshotBatchRequest`

```py
class SnapshotBatchEntry(BaseModel):
    account_id: int
    balance: float | None = None
    notes: str | None = None

class SnapshotBatchRequest(BaseModel):
    as_of_date: date
    entries: list[SnapshotBatchEntry]
```

Response body: `SnapshotBatchResponse { written: int }`

- Entries with `balance is None` are skipped (count not incremented).
- Same-day re-entry upserts via the unique constraint.
- 400 on unknown account_id / archived account / negative balance, with
  `detail` text that includes the account name where applicable.

### `GET /api/net-worth/latest`

Response body: `list[LatestBalanceResponse]`

```py
class LatestBalanceResponse(BaseModel):
    account_id: int
    account_name: str
    account_type: str    # serialized as the Account.type string ("checking", etc.)
    balance: float | None
    as_of_date: date | None
    model_config = {"from_attributes": True}
```

- One row per non-archived account, sorted by `account_name`.
- Accounts with no snapshots are still listed with `balance=None`,
  `as_of_date=None`. This matches the plan's "yes, this account exists,
  no snapshot yet" semantics.

## Snapshot batch modal behavior

`frontend/src/components/SnapshotBatchModal.tsx` — props are
`{ open, onCancel, onSubmit, accounts, latestBalances, submitting?, errorMessage? }`.

- The date input defaults to today (`yyyy-mm-dd` ISO) and has
  `max={today}` to discourage future-dating but the backend doesn't
  reject future dates.
- Inputs are NOT pre-filled. The hint line `last: $X on YYYY-MM-DD`
  appears under each input only if `latestBalances` has a row for that
  account with a non-null `balance` and `as_of_date`. Hint amount is
  formatted with `toLocaleString` 2 decimals; the date is the raw ISO
  string from the API.
- On save the modal filters blanks, parses numbers, validates non-negative
  client-side, and calls `onSubmit(asOfDate, entries)`. Errors come back
  via the `errorMessage` prop (from the `ApiError.message` set in the
  parent's `useMutation` `onError`).
- If no entries are filled, save shows an inline "Enter at least one
  balance to save." rather than POSTing an empty batch.

## Tricky bits / lessons

- **Autogenerate quirk** (recurring): every new migration tries to
  `drop_index` the partial-unique indexes on `coast_fire_scenarios.is_active`
  and `mortgage_scenarios.is_active`. Hand-edit those drops out of any
  new migration's upgrade/downgrade. Documented in the migration
  doc-string and originally surfaced in step 4's handoff.
- **SQLite upsert** uses `sqlalchemy.dialects.sqlite.insert(...)
  .on_conflict_do_update(index_elements=[...], set_={...})`. Works against
  the `UNIQUE (account_id, as_of_date)` constraint without referencing
  the constraint by name.
- The `LatestBalanceResponse.account_type` field is serialized as the
  raw enum string ("checking" / "credit_card" / etc.), not as the
  Pydantic `AccountType` StrEnum. The frontend assumes the same string
  union as `accounts.ts AccountType` and casts `as AccountType` at the
  query boundary.
